# スケジュール実行（Phase 17.2）

## 構成

[登録ジョブ](registered_jobs.md)に実行予定を1件設定する。
Workbenchのバックグラウンドスレッドが10秒ごとに予定を確認し、
Phase 17.1と同じ実行器へ渡す。追加サーバー、外部cron、依存ライブラリは不要。
定義・予定・履歴は既存の `SHIROKUMA_STATE_DIR/jobs.sqlite3` に保存する。

Workbenchサーバーが稼働している間は、ブラウザを閉じても実行する。
Workbenchサーバーの停止中やホストのスリープ中は実行できない。
ウェアハウスが休止中なら既存のAuto-Wakeを利用する。

## 設定と使い方

ジョブ画面で登録済みジョブを選び、実行引数とスケジュールを設定する。
初期状態は無効。「有効」にして保存すると次回実行時刻を表示する。
無効にして保存すると将来の実行を止める。実行中の処理は中断しない。

| 種類 | 設定 | 次回の計算 |
|---|---|---|
| 一定間隔 | 1〜10,080分 | 保存時刻から指定分後。以後は前回の予定時刻を基準とする |
| 毎日 | 時刻 `HH:MM` とIANAタイムゾーン | 指定地域の次の実行時刻。既定タイムゾーンは `Asia/Tokyo` |

設定を保存し直すと次回時刻を計算し直す。
日次の夏時間切替で存在しない時刻はその日の実行を省略し、
同じ時刻が2回来る日は最初の1回だけを対象とする。
内部時刻はUTCで保存し、日次の地域時刻との変換は標準ライブラリの `zoneinfo` を使う。

引数は保存した値を繰り返し使う。日付引数が翌日の日付へ自動更新されることはない。
各実行では最新の登録ジョブ定義を検証し、そのコピーを実行履歴に残す。
定義を変えた場合は、予定に保存した引数・権限との整合を確認する。

## 権限と履歴

所有者だけが予定を保存・有効化・無効化できる。管理者は他の所有者の予定を閲覧できる。
閲覧者は利用できず、データ作成者は既存ポリシーで許可されたSQLのみ実行できる。
保存時の認証済み利用者・選択ロール・認証モードを固定し、発火前に再検証する。
権限失効やローカル／共有モードの切替後は予定を停止し、確認・再保存を必要とする。
資格情報そのものは保存しない。

実行履歴には手動／スケジュールの区別と予定時刻を残す。
SQL結果行を保存せず、処理件数・所要時間・安全なエラーコードを記録する。

## 競合・停止・再起動

- 手動実行と予定実行を合わせて、同じ状態ディレクトリで同時に1件だけ実行する。
- 他ジョブが実行中の予定はスキップし、待ち行列へ積まない。
- 同時刻に複数の予定を設定すると競合するため、実行時間を考慮して予定時刻をずらす。
- 予定から60秒以上遅れて検出した場合もスキップする。停止中の回数分を後からまとめて実行しない。
- 複数のWorkbenchプロセスが同じ状態を使っても、ローカルファイルロックとSQLiteトランザクションで予定消費を調停する。
- 予定を消費した記録と実行受付を同時に保存する。中断した実行は既存の復旧処理で結果不明となり、自動再実行しない。

SQLの反映と台帳更新を一つのトランザクションにはできないため、
障害をまたぐexactly-onceやジョブ全体のロールバックは保証しない。
実行予算の900秒は処理境界で確認し、実行中のSQLやPythonスレッドの強制終了期限ではない。

バックアップには予定も含まれる。復元した台帳の予定はすべて無効化する。
反映先と未完了履歴を確認してから、所有者が必要な予定を再度有効にする。

## HTTP API

既存Workbenchの認証、選択ロール、同一オリジン制限を利用する。

| 操作 | API | 応答 |
|---|---|---|
| 予定一覧 | `GET /api/jobs/schedules` | `{"schedules":[...]}` |
| 保存・有効化・無効化 | `POST /api/jobs/schedule` | `{"schedule":...}` |

一定間隔の入力例：

```json
{
  "name": "count_orders",
  "kind": "interval",
  "every_minutes": 60,
  "arguments": {"as_of": "2026-10-18"},
  "enabled": false
}
```

日次の場合は `every_minutes` の代わりに
`"kind":"daily", "time":"02:00", "timezone":"Asia/Tokyo"` を設定する。
本文から利用者、ロール、認証モード、次回時刻を指定することはできない。
既存の予定を停止するだけなら `{"name":"count_orders","enabled":false}` を送る。
この操作は保存済みの権限・引数を変更せず、実行権限や編集中の引数に依存しない。
