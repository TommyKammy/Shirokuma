# Workbench UI デザイン規則（2026-10-18 改修）

Workbench（`tools/local_experiment/workbench/index.html`）の画面構成と共通部品の規則。
外部CDN・フォント・ビルド基盤は使わず、HTML・CSS・JavaScriptの単一ファイルで配信する。
API契約と実行の意味は変えていない。画面の非表示・無効化は操作の案内であり、権限はサーバーが検証する。

## Databaseモードの利用条件と案内

2026-10-29の[機能一覧と利用条件](database-capability-matrix-2026-10-29.md)を表示契約とする。対応済みの手動WAP・管理Mart・取り込みと、未接続のdbt・AI・統合監査・コンピュート管理を機能名で区別する。パネルの案内は固定IDへ結び付け、フォームの挿入順序に依存させない。
利用不可の理由は、機能未接続、既知のrole条件不一致、対象未選択、認可確認中／context利用不可に分ける。未知・不許可・非READYのDBを推測で区別して表示しない。各パネルの利用条件はWorksheetの現在選択と独立し、操作結果・UNKNOWN等のstatusを補足案内で上書きしない。
無効操作にも日英の説明を付け、Worksheet結果保存の代わりにTable全件Export、未対応AIの代わりにSQL・手動WAP、統合監査の代わりに個別履歴など、対応済みの確認先を示す。DB内adminとplatform管理権限は分け、管理者へ切り替えるだけで未接続機能が使えるとは案内しない。

> **Atlas 適用後（2026-11-18）**：Databaseモードの利用条件と案内はそのまま使う。画面の骨格だけを「Atlas 版の共通ルール」1〜3に置き換える。

## 画面構成

| 領域 | 内容 |
| --- | --- |
| ヘッダー | 製品名・環境、ウェアハウス状態と起動／休止、ロール、AI設定（管理者）、言語 |
| ナビゲーション | データを扱う（SQL・取り込み・データ変換・ジョブ・AI Bears）／カタログ／監視・管理 |
| ページ見出し | 見出し・1行説明・ページ単位の操作を同じ行に置く |
| ページ内ビュー | 取り込み＝ファイル・ステージ、データ変換＝モデル・更新対象、ジョブ＝ジョブ・実行履歴・通知 |

ジョブ・ステージ・更新対象は同じ流れに揃える。

1. 一覧：名前、所有者、自動実行の状態と次回予定、直近の結果を表示し、選択行を強調する。
2. 詳細：左に定義（保存）、右に今すぐ実行と自動実行（保存・停止）を置く。
3. 結果：実行後は状態を表示し、実行履歴とステップ詳細へ移動できる。

未保存の定義がある間は手動実行を無効にし、保存済みの版だけを実行する。
手動実行の結果は送信時のジョブ・選択・ロールに結び付け、応答前に対象を変えた場合は新しい選択へ表示しない。
受理済みの実行は履歴に反映し、表示上の都合で「実行失敗」と扱わない。結果の「実行詳細を表示」はその実行IDで開く。
実行履歴は閲覧できる直近100件だけを取得するため、見つからない場合は「直近100件に履歴なし」と表現する。
「実行詳細を表示」で履歴の絞り込みを戻す際は、同じ実行IDが選択済みでも一覧を再描画し、絞り込み・行・詳細を揃える。

> **Atlas 適用後（2026-11-18）**：この表のヘッダー・ナビゲーション・ページ見出しは「Atlas 版の共通ルール」1の構成に置き換える。ページ内ビューの分け方（取り込み＝ファイル・ステージ、データ変換＝モデル・更新対象、ジョブ＝ジョブ・実行履歴・通知）は、Atlasの「取り込み・ステージ」「データ変換」「ジョブ」に引き継ぐ。

## SQLワークシート

- 広い画面は探索・エディター・結果を並べる。1024px以下はエディター、折りたたんだ探索、結果の順に積む。
- 390px程度ではエディターを短くし、実行ボタンをエディター直下に置く。長いSQLは内部スクロールと高さ調整で編集する。
- Database mode（UX-D1）では共通ツリーの単クリックは詳細表示であり、SQL名の挿入・新しいSQL・実行先の変更は詳細の明示ボタンで行う。
  旧形式（Database mode以外）の探索だけが「選ぶとカーソル位置に名前を挿入」の動作を残す。
- Database modeの配置（2026-10-20、UX-D1モックに整合）：左は検索・更新→Database／Schema／Tables・Views（種類アイコン）→探索コンテキスト。
  作業領域は「詳細／ワークシート」の1本のタブ列、詳細はパンくず・名前・SQL名・主操作（新しいSQLを主ボタン）、
  ワークシートは実行コンテキスト（DB／Schema／実行role／mode／Warehouse／最大行数）をエディター上、取消と実行を下に置く。
  履歴の復元は結果の下にあり、1024px以下では探索を上部の折りたたみ行にする。記録は [UX-D1探索・SQL記録](database-ux-d1-explorer-sql-report-2026-10-20.md)。
- 各タブ右側の × はローカルのワークシートとその SQL を削除する。最後の1枚は理由を添えて無効化する。
  空欄と既定の注文サンプルそのものだけは直接閉じ、それ以外は保存済み SQL も含め削除確認を出す（編集履歴は持たない）。
- アクティブなタブを閉じると右隣、右がなければ左隣へ移る。他のタブを閉じても編集中の SQL と選択範囲を保つ。
  削除とアクティブIDを既存のローカル保存へ反映し、追加名は残っている番号の最大値から採番する。
- Copilot の生成 SQL は開始時のワークシートが残り SQL が変わっていない場合だけそのシートへ保存し、削除・編集後も生成結果は表示する。

> **Atlas 適用後（2026-11-18）**：SQLワークシートの配置はUX-A3でAtlasの「実行コンテキスト→エディター→結果」に置き換える。タブの削除・隣接移動・SQL保持の動作、実行範囲、実行時コンテキストの固定、古い応答の破棄はそのまま残す。SQL提案はSQL画面の折りたたみ（見本の `sqlProposalHTML`）として残し、AI Bearsからの受け渡しと併存させる。SQL提案から取り込んだSQLは、開始時のワークシートが残りSQLが変わっていない場合だけそのシートへ保存し、削除・編集後も提案内容は表示する。

## データ探索とコンピュートの情報設計（2026-11-04）

- データ探索の詳細は、パンくず・名前・SQL名の直下に「新しいSQLを開く／SQL名を挿入／このSchemaを実行先にする」だけを置く。保存済みリネージュはLineageタブに一本化する。
- 複製・書き出し・カタログ登録解除は、内容タブの下の「テーブルの管理」に分ける。登録解除は別の区画に置き、データ保持と名前確認を短く示す。無効な理由はその区画に表示し、DB／Schemaの概要では区画ごと隠す。書き出しの受領記録は要求後だけ表示する。
- コンピュートは「稼働状態の要約→操作できる内容と全DBへの影響→操作→休止できない理由→自動休止→使用量と空き容量→運用診断」の順にする。要約は観測からの経過時間を示し、未取得・取得不可・非対応・古い観測を区別する。エンジン検証は別記録として扱う。
- 設定上の割当・実使用量・Nodeの空き容量は別ラベルで並べる。使用量・容量と運用診断（稼働の記録／宣言とポリシー／ログとテレメトリ）は、操作と同じプラットフォーム権限・現在／上限adminの条件で表示する。

> **Atlas 適用後（2026-11-18）**：情報の順序と配置はUX-A3・UX-A6でAtlasの「データ探索」「コンピュート & ガバナンス」に置き換える。設定上の割当・実使用量・Nodeの空き容量を分ける規則、観測の鮮度、操作と同じ権限条件で表示する規則はそのまま残す。

## Data Engineer Bear

操作ごとに必要な入力だけを表示し、送信内容にも現在の操作の項目だけを含める。非表示の入力は無効化し、下書きは保持する。

| 操作 | 表示する入力 | 送信する項目 | ボタン |
| --- | --- | --- | --- |
| generate | 説明、SQL（任意・優先） | `request`、`sql` | SQLを生成 |
| stage | 説明、SQL、サンドボックスのテーブル名 | `request`、`sql`、`stage_table` | ステージングして検証 |
| publish | 公開するサンドボックスのテーブル | `publish` | テーブルを公開 |
| refresh | 更新するWAPモデル、SQL（任意、空欄は保存済みSQL） | `refresh`、`sql` | テーブルを更新 |
| rollback | 戻すテーブル、スナップショットID（数字のみ・文字列で送信） | `rollback`、`snapshot_id` | 指定スナップショットへ戻す |

すべて `bear: data` と `action` を明示する。選べる操作はサーバーと同じく閲覧者がgenerate、データ作成者がgenerate・stage、
管理者が全操作。登録済みの更新対象はデータ変換画面からのみ更新でき、サーバーが拒否する。
実行待ち中もボタンは無効のままにし、成功・失敗後は現在の操作とロールに合わせてフォームと実行ラベルを同期する。

## 共通部品

- **トークン**：色・余白・角丸・文字サイズは `:root` の変数だけを使う。暗い配色も変数で切り替える。
- **文字**：本文13px、表12〜12.5px、見出し20px／14px。識別子・SQL・データは等幅。
- **ボタン**：通常（補助）、`primary`（保存・確定）、`run`（今すぐ実行）、`stop`（自動実行の停止）、`danger`（削除）。
  1つの領域で `primary` は1つまでにする。
- **状態表示**：`badge`／`status-line` に `tone-ok`・`tone-run`・`tone-warn`・`tone-bad` を付ける。
  色に加えて記号（✓・●・!・✕）と文言で状態を示す。
- **メッセージ**：失敗は `error`（原因の全文）、要確認・復旧案内は `callout warn`、補足は `callout info`／`help`。
  重要な失敗や復旧案内は一時表示にせず、対象の近くに残す。
- **空・読込**：空の一覧には最初にできる操作を書く。読込中は対象の場所に「読み込み中…」を出す。
- **表**：見出しを固定し、横長の表は表の中だけを横スクロールする。NULLは斜体で区別する。

> **Atlas 適用後（2026-11-18）**：トークン・文字・ボタン種別・状態表示・空／読込・表の規則はそのまま使う。メッセージは「Atlas 版の共通ルール」4、影響表示と赤い確定ボタンは3、成功後の主ボタンは5に従う。

## 自動実行（スケジュール）

ジョブ・ステージ・更新対象で配置と用語を揃える。

- 上段の状態欄：有効／無効、実行方式、次回予定（タイムゾーン付き）、前回の状態、停止ボタン。
- 下段のフォーム：実行方式に必要な項目だけを表示し、有効化のチェックと「スケジュールを保存」で確定する。
- 停止は保存済みの予定だけを無効にする。フォームが未保存・不正でも停止でき、編集中の値は保存も破棄もしない。
- 一定間隔の次回予定はブラウザのタイムゾーン、カレンダー予定は指定したタイムゾーンで表示する。表示だけで予定計算は変えない。
- 更新対象で結果不明が残る間は、状態欄より先に復旧手順を表示し、手動更新の成功まで有効化を許可しない。

> **Atlas 適用後（2026-11-18）**：自動実行の配置と用語は、ジョブ・ステージ・更新対象でそのまま揃える。画面ごとの置き場所だけをAtlasの各画面へ移す。

## アクセシビリティ

- ナビゲーション・ページ内ビュー・検査タブは矢印キー、Home、Endで移動する。フォーカス枠は常に表示する。
- すべての入力にラベルを付ける。状態の変化は `role="status"`、失敗は `role="alert"` で通知する。
- 動きは実行中表示だけにし、`prefers-reduced-motion` で止める。
- API・ユーザー入力は `textContent` で表示し、HTMLとして解釈しない。

> **Atlas 適用後（2026-11-18）**：この節の規則は「Atlas 版の共通ルール」7で拡張する。320pxの確認、44pxのタップ領域、`role="status"`／`alert`、矢印キー移動、フォーカス枠はそのまま必須とする。

## Atlas 版の共通ルール（2026-11-18）

確定した [Shirokuma Atlas モックアップ](../design/assets/ui_mockups/shirokuma-atlas.html)（`03ece343`）を
現行 Workbench に適用するときの共通規則。UX-A1〜A7 の実装者は、画面ごとの見本の差異より

既存の契約（権限の再確認、取消、UNKNOWN の照合、公開履歴、古い応答の破棄）は変えない。

1. 見本に同じ操作・状態がある → 見本の文言・配置・状態表示に合わせる。

3. それでも決まらない → 「要確認」に理由を付け、監督者に送る。独断で新しい画面・用語・状態を作らない。

### 1. 画面構成

**ナビゲーション。** 左ナビは次の4区分に固定し、ラベルを折り返さない。

| 区分 | 項目 |
| --- | --- |
| データを扱う | ホーム、データ探索、SQL ワークシート、取り込み・ステージ、データ変換、ジョブ、AI Bears |
| 運用管理 | データベース管理、監査ログ、コンピュート & ガバナンス |
| お気に入り | ピン留めしたテーブル・DB（利用終了したDBは出さない） |
| ワークスペース | 現在のDB／スキーマ、Warehouse（コンピュート画面へのリンク） |

- 「データを扱う」「運用管理」は見出しであり、クリック対象にしない。現在地は `aria-current="page"` で示す。
- 320pxでは左ナビを隠し、上部の `details` メニューに同じ項目を出す。横スクロールでナビを出さない。
- 画面下部にテーマ切替と言語・ロール・AI設定（本体へのリンク）を含むユーザーメニューを置く。ロールは現在の上限ロールを表示し、変更時は既存の再認可を通す。

**上部バー。** 左からパンくず、環境バッジ（現行ヘッダーが表示している環境名をそのまま出す。固定文字列を新設しない）、コンピュート状態チップ、⌘K（検索・コマンド）、主ボタン「SQL を開く」の順に置く。

- コンピュート状態チップは `利用可能`・`休止中`・`切替中`・`状態不明`・`観測期限切れ` を表示し、クリックで「コンピュート & ガバナンス」へ移動する。
- 上部バーとページ見出しに日付を出さない。日時は一覧・履歴・監査の各行、または詳細に出す。
- ページ見出し直下に定型の説明文を置かない。説明が必要なときは、見出し横の状態行、空状態、または表のキャプションに1行だけ置く。既存の `database-page-description` のような常設リード文は削除する。
- 詳細画面は「← 一覧に戻る」をH1の上に置き、H1と同じ行に主ボタンを1つだけ置く。副操作はツールバー、「管理」の折りたたみ、または行内メニューに移す。

**URLと復元。** 画面・詳細・確認はハッシュルートで表し、再読み込みと深いリンクから復元する。

| 画面 | 経路の例 |
| --- | --- |
| ホーム | `#home` |
| データ探索 | `#explore`、`#explore/iceberg.analytics.orders` |
| SQL | `#sql` |
| 取り込み | `#ingestion`、`#ingestion/stages` |
| データ変換 | `#transformation` |
| ジョブ | `#jobs`、`#jobs/daily-sales` |
| AI Bears | `#bears` |
| DB管理 | `#databases`、`#databases/{id}`、`#databases/create`、`#databases/retire~{id}`、`#databases/confirm~{id}` |
| 監査ログ | `#audit`、`#audit/{event-id}` |
| コンピュート | `#compute` |

- 経路に選択対象（DB、スキーマ、テーブル、実行ID）を含める。選択をURLに持てない画面は、再読み込み後に同じ画面の初期状態へ戻し、勝手に別の対象を選ばない。
- 戻る／進むで、確認ダイアログや未確定の操作を自動再送しない。

### 2. 状態の一致

画面ごとに独自の状態判定をせず、同じサーバー値から同じ表示を作る。最低限、次の対応を守る。

| 対象 | サーバーの値 | 表示 | 操作 |
| --- | --- | --- | --- |
| コンピュート | `physical_state=active` | 利用可能 | SQLを実行できる |
| コンピュート | `chilled` | 休止中 | 新規SQLを止める。起動は管理者のみ |
| コンピュート | `transitioning` | 切替中 | 新規SQLと起動・休止を止める |
| コンピュート | `unknown`／`observation_error` | 状態不明 | 操作を止め、状態の照合を先に案内する |
| コンピュート | `observed_at` が60秒超 | 観測期限切れ | 起動・休止の操作だけを再観測まで止める。SQLは止めない。古い値を「現在」と書かない |
| DB | `READY` | 利用可能 | SQLの選択肢に出す |
| DB | `CREATING`／作成の `BLOCKED` | 作成中／確認待ち | SQLの選択肢に出さない |
| DB | `RETIRING`／`RETIRED` | 利用終了（処理中／完了） | SQLの選択肢に出さない。現在の選択だけは理由を添えて残せる |
| クエリ・実行 | `QUEUED`／`RUNNING` | 待機中／実行中 | 取消できる。終端まで次の実行を抑止する |
| クエリ・実行 | `UNKNOWN` | 結果不明 | 再送しない。照合だけを出す |
| クエリ・実行 | `FINISHED`／`FAILED`／`CANCELED` | 成功／失敗／取消 | 終端。同じ要求を再送しない |
| 休止の妨げ | `/api/v1/runtime` の `blockers` | 内訳（runtime_operations / admissions / unknown / creation） | 件数と内訳を表示する。妨げがある間は休止を無効にする。可否の最終判定はサーバーの停止応答 |

- コンピュートが `休止中`・`切替中`・`状態不明` の間は、SQLの実行ボタンを無効にし、ボタンの横に理由を1行で出す。実行ボタンを隠さない。
- `観測期限切れ` の間もSQLは実行できる。起動・休止の操作だけを再観測まで無効にし、状態チップに「観測期限切れ」と出す。
- 実行中・結果不明、DB／スキーマ未選択、権限なしによるSQLの抑止は既存規則のまま残す。コンピュート状態による抑止は `休止中`・`切替中`・`状態不明` の3つだけとする。
- 利用終了したDBは、データ探索・SQL・取り込み・データ変換・ジョブの選択肢から外す。URLや保存済みの選択が残っている場合は、対象を勝手に差し替えず「利用終了のため実行できません」と出す。
- `UNKNOWN` は成功にも失敗にも丸めない。照合が終わるまで「結果不明」のまま、取消・再実行・公開を止める。
- 照合済み（reconciled）を理由に休止を妨げないのは、サーバーが `execution_closure` を記録した処理、または終端状態（`FINISHED`・`FAILED`・`CANCELED`）の処理だけとする。画面側の「確認済み」「照合記録あり」だけでは解除しない。
- ロール・DB・スキーマ・実行IDを変えたら、飛んでいる応答を破棄する。既存の `identity`・`epoch`・`request` の世代照合を使い、古い応答を新しい選択へ描かない。
- 画面間で同じ状態を出すときは、ナビのバッジ、上部バー、ページ本文、確認ダイアログで同じ文言を使う。1か所だけ古い値なら、その画面の状態を再取得してから操作させる。
- 操作の可否はサーバーの capability を優先する。画面で無効にした操作にも、理由と `aria-describedby` を付ける。サーバーが拒否した場合は、拒否コードとメッセージをその場に残す。

### 3. 影響の表示

全件置換・公開の置き換え・利用終了・休止では、確定ボタンの直前に影響を1行で出す。ボタン名に影響を書き、破壊的な操作は赤い `danger` にする。影響の数値はサーバーのプレビュー応答だけを使い、画面で概算しない。

| 操作 | 影響の1行（日本語） | 確定ボタン |
| --- | --- | --- |
| 取り込み・新規作成 | 新規テーブルを作成し N 行を書き込みます。 | 作成して取り込む |
| 取り込み・追加 | 既存 N 行に M 行を追加します（合計 K 行）。 | M 行を追加する |
| 取り込み・全件置換 | 既存 N 行をすべて削除し、M 行に置き換えます。 | N 行を削除して置き換える（赤） |
| 取り込み・キーで更新 | U 行を更新、A 行を追加します（合計 K 行）。 | M 行を更新・追加する |
| 公開・置き換え | 公開中の N 行を M 行に置き換えます。参照中のロール: … | 置き換えて公開（赤） |
| 公開・新規 | 新しい MARTS テーブルを M 行で作成します。 | MARTS に公開 |
| 利用終了 | スケジュール N 件を停止し、アクセス M 件を終了します。データと操作履歴は保持します。 | 利用終了を開始（赤） |
| 休止 | 全利用者の新規処理を止めます。ジョブ（N 件）とSQLワークシート（N 件）は起動まで実行できません。永続ストレージは保持し、自動では再開しません。 | 確認して休止（赤） |

- 影響の1行は、確定ボタンと同じブロックに置く。トースト、別画面、折りたたみの中だけに出さない。折りたたみは詳細の補足に使う。
- 下流の変換がある取り込みでは、影響の1行の下に「下流の変換: …（再ビルドまで公開内容は変わりません）」を続ける。下流がない場合は行を出さない。
- 数値が取得できないときは「影響を取得できません」と表示し、確定を無効にする。0行・0件と推測しない。
- プレビュー後に取込先・入力・ロール・DBが変わったら、そのプレビューを無効にし、再プレビューを要求する。既存の fingerprint と `expected_preview_fingerprint` の仕組みを使う。
- 利用終了の影響には、停止するスケジュール、依存関係、開始を妨げる処理、アクセスが終わる利用者、データの保持をこの順で出す。妨げがある間は確定ボタンを無効にし、理由をその行に出す。
- 休止は、サーバーが妨げを返すと拒否される（`WAREHOUSE_BUSY`）。妨げがある間は「確認して休止」を無効にし、内訳を出す。件数・内訳は `/api/v1/runtime` の `blockers` と既存ジョブAPI（有効なスケジュール）を正とし、開いているワークシート数は画面のローカル状態を使う。新しいAPIは作らない。

### 4. メッセージ

- メッセージ領域は画面ごとに1か所。H1の下、または操作対象のセクションの直前に置く。同じ内容を状態行・トースト・エラー欄の3か所に重複して出さない。
- その画面の操作で出たメッセージだけを表示する。画面を移ったら消す。引き継ぐのは、次の受け渡しで出たメッセージだけとする。
  - AI Bears → SQL：「承認した案をワークシートに渡しました。未実行です。」
  - AI Bears → データ変換：「変換案をモデル入力に準備しました。保存・ビルド・品質検査が必要です。」
  - データ探索 → SQL：「選択したテーブルをSQLで開きました。未実行です。」
  - DB詳細 → SQL：「DBとスキーマを引き継ぎました。未実行です。」
  - 取り込み → データ変換：「取り込んだRAWから変換モデルを作成できます。」
  - 公開 → データ探索：「公開テーブルを開きました。」
  - ジョブ実行 → ジョブ詳細：「実行を受け付けました。」
- 進行中は `role="status"`、失敗は `role="alert"`。成功メッセージには次の操作を1つだけ添える。同じ成功を二重に出さない。
- 失敗は、画面全体を「操作に失敗しました」で置き換えない。操作したコントロールの近くに、サーバーのコードとメッセージ、再試行の可否を残す。入力値は保持する。
- 自動消去するのは補足だけ。失敗・要確認・復旧案内は、利用者が閉じるか、次に成功するまで残す。
- APIやユーザー入力の文字列は `textContent` で表示し、HTMLとして解釈しない。

### 5. 次の操作

- 1つの画面・領域で `primary` は1つだけにする。成功後の主ボタンも1つにする。
- 成功後の主ボタンは次のとおり。
  - 取り込み完了 → 「このデータから変換モデルを作成」
  - データ変換の公開完了 → 「公開テーブルを開く」
  - DB作成がREADY → 「SQLで使う」（新しいワークシートを開く）
  - ジョブ実行の受付 → 「実行詳細を表示」
- SQLの実行ボタンは、結果の有無にかかわらず常に主ボタンのままにする。結果の保存などは副操作に置く。
- READY後のDB詳細では「SQLで使う」を先頭に置き、「利用終了」は「管理」の下へ移す。利用終了を主ボタンの隣に置かない。
- 公開後は「公開テーブルを開く」を主にし、同じ内容の再公開を主ボタンとして残さない。再公開が必要なときは「管理」から明示する。
- 成功後に同じ操作を繰り返すと危険な場合（公開・利用終了・全件置換）は、元の確定ボタンを無効にし、次の操作だけを出す。二重送信は既存の冪等キーと `pending` で防ぐ。

### 6. 表記

- 時刻は `YYYY-MM-DD HH:MM JST`。秒（`:SS`）は監査ログの一覧・詳細とSQLの受付時刻に付ける。それ以外は分までにする。`<time datetime="…">` にはUTCのISO値を入れ、表示だけJSTにする。
- 日時入力はJSTとして解釈する。`datetime-local` の値に「JST」のラベルを付け、送信時に明示的に `+09:00` またはUTCへ変換する。ブラウザのタイムゾーンで勝手に解釈しない。
- UTCは監査記録の詳細だけ、JSTの下に小さく併記する。一覧・見出し・確認画面の主表示にUTCを出さない。
- 用語は次に統一する。日本語UIでは状態名の後ろに英語を括弧書きしない。

| 現行の表記 | Atlas の表記 |
| --- | --- |
| retired／retiring、廃止 | 利用終了（完了／処理中） |
| chill／Chill | 休止 |
| wake／Wake | 起動 |
| WAP | データ変換（画面・操作名） |
| replace／append／upsert | 全件置換／追加／キーで更新・追加 |
| UNKNOWN（処理） | 結果不明 |
| unknown（コンピュート） | 状態不明 |
| Reconciled | 照合済み（休止の可否は §2 の条件で判断） |
| DB management | データベース管理 |
| Audit Log | 監査ログ |
| Data Explorer | データ探索 |
| Jobs | ジョブ |
| Compute & Governance | コンピュート & ガバナンス |

- 英語UIも同じ語彙を使う。`Retire`／`Retired`、`Chilled`、`Outcome unknown`、`Reconciled`、`Data transformation` とし、`WAP` を画面文言に残さない。
- 新しい文言は `base_i18n.js` の `i18n.ja` と `i18n.en` の両方に登録する。識別子・SQL・テーブル名・ロール名は翻訳しない。
- 行数は `N 行`、件数は `N 件`、容量は `MiB`、時間は `1.8 秒`。桁区切りを入れる。相対時刻（「3分前」）は補助にだけ使い、詳細には絶対時刻を併記する。

### 7. アクセシビリティ

- 320px・390px・1440pxで、ページ全体に横スクロールを出さない。長い表は `.tablewrap` の中だけを横スクロールする。確認は `document.documentElement.scrollWidth <= window.innerWidth` で行う。
- タップ領域は44×44 CSS px以上。ボタン、入力、選択、タブ、表の行内操作を対象にする。600px以下では `min-height:44px` を基本にする。
- フォーカス枠は常時表示する。`:focus-visible` に2px以上のアウトラインと `outline-offset` を付け、`outline:none` だけの指定をしない。スキップリンクを先頭に置く。
- 画面遷移・操作完了後は、H1、メッセージ、または操作したコントロールへフォーカスを戻す。確認ダイアログは開いた要素へ戻す。
- 非同期の進行・成功は `role="status"`（`aria-live="polite"`）、失敗は `role="alert"`。処理中は `aria-busy="true"` を対象のボタンに付ける。
- ナビゲーション、画面内タブ、検査タブは矢印キー・Home・Endで移動する。`aria-selected` と roving `tabindex` を同期する。
- ⌘Kのパレットは矢印キーで選択し、Enterで決定、Escで閉じる。権限のないテーブルと利用終了したDBは候補に出さない。
- `prefers-reduced-motion: reduce` では、実行中表示以外のアニメーションを止める。
- 色だけで状態を伝えない。`✓`・`●`・`!`・`✕` と文言を併用する。
- API・ユーザー入力は `textContent` で描画する。`innerHTML` にデータを渡さない。

`make verify-local-experiment` と `make verify-design-context` を通す。

### Databaseモードの手動DataOps（2026-10-20、P3-5）

- 手動Ingestは入力bytesと型付きpreviewを固定し、明示modeと作成先／既存Tableを確認して実行する。入力やcontextを変更した場合は再previewが必要。
- 手動WAPは独立したDB／Schema／roleを持ち、model版・build・audit・publicationを表示する。publish／rollbackはadminに限定し、role切替後は許可済みmetadataを明示的に再取得する。
- Explorerの実TableにCSV／JSONLのSnapshot固定Exportを提供する。receiptとdownloadは取得時に再認可し、grant失効後の結果・fileを表示しない。View全件ExportとWorksheet結果保存等の未対応入口は無効を維持する。
- 各DataOpsパネルと受付済みoperationは元contextを保持し、WorksheetのSQL／DB／Schema／保存role／Warehouse／modeやExplorer選択を変更しない。応答不明は元の同一keyで明示照会し、別identityへ切り替えて回復しない。
- 通常CLI・3DBの実engine・実ブラウザーの正負証拠と残件は、[P3-5受入報告](database-p3-5-normal-entry-acceptance-report-2026-10-20.md)を参照。所有者の最終操作性評価はPhase 5に残す。
