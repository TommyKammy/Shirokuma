# Workbench UI デザイン規則（2026-10-18 改修）

Workbench（`tools/local_experiment/workbench/index.html`）の画面構成と共通部品の規則。
外部CDN・フォント・ビルド基盤は使わず、HTML・CSS・JavaScriptの単一ファイルで配信する。
API契約と実行の意味は変えていない。画面の非表示・無効化は操作の案内であり、権限はサーバーが検証する。

## 画面構成

| 領域 | 内容 |
| --- | --- |
| ヘッダー | 製品名・環境、ウェアハウス状態と起動／休止、ロール、AI設定（管理者）、言語 |
| ナビゲーション | データを扱う（SQL・取り込み・データ変換・ジョブ・AI Bears）／カタログ／監視・管理 |
| ページ見出し | 見出し・1行説明・ページ単位の操作を同じ行に置く |
| ページ内ビュー | 取り込み＝ファイル・ステージ、データ変換＝モデル・更新対象、ジョブ＝ジョブ・実行履歴・通知 |

ジョブ・ステージ・更新対象は同じ流れに揃える。

1. 一覧：名前、所有者、自動実行の状態と次回予定、直近の結果を表示し、選択行を強調する。
2. 詳細：左に定義（保存）、右に今すぐ実行と自動実行（保存・停止）を置く。
3. 結果：実行後は状態を表示し、実行履歴とステップ詳細へ移動できる。

未保存の定義がある間は手動実行を無効にし、保存済みの版だけを実行する。

## 共通部品

- **トークン**：色・余白・角丸・文字サイズは `:root` の変数だけを使う。暗い配色も変数で切り替える。
- **文字**：本文13px、表12〜12.5px、見出し20px／14px。識別子・SQL・データは等幅。
- **ボタン**：通常（補助）、`primary`（保存・確定）、`run`（今すぐ実行）、`stop`（自動実行の停止）、`danger`（削除）。
  1つの領域で `primary` は1つまでにする。
- **状態表示**：`badge`／`status-line` に `tone-ok`・`tone-run`・`tone-warn`・`tone-bad` を付ける。
  色に加えて記号（✓・●・!・✕）と文言で状態を示す。
- **メッセージ**：失敗は `error`（原因の全文）、要確認・復旧案内は `callout warn`、補足は `callout info`／`help`。
  重要な失敗や復旧案内は一時表示にせず、対象の近くに残す。
- **空・読込**：空の一覧には最初にできる操作を書く。読込中は対象の場所に「読み込み中…」を出す。
- **表**：見出しを固定し、横長の表は表の中だけを横スクロールする。NULLは斜体で区別する。

## 自動実行（スケジュール）

ジョブ・ステージ・更新対象で配置と用語を揃える。

- 上段の状態欄：有効／無効、実行方式、次回予定（タイムゾーン付き）、前回の状態、停止ボタン。
- 下段のフォーム：実行方式に必要な項目だけを表示し、有効化のチェックと「スケジュールを保存」で確定する。
- 停止は保存済みの予定だけを無効にする。フォームが未保存・不正でも停止でき、編集中の値は保存も破棄もしない。
- 一定間隔の次回予定はブラウザのタイムゾーン、カレンダー予定は指定したタイムゾーンで表示する。表示だけで予定計算は変えない。
- 更新対象で結果不明が残る間は、状態欄より先に復旧手順を表示し、手動更新の成功まで有効化を許可しない。

## アクセシビリティ

- ナビゲーション・ページ内ビュー・検査タブは矢印キー、Home、Endで移動する。フォーカス枠は常に表示する。
- すべての入力にラベルを付ける。状態の変化は `role="status"`、失敗は `role="alert"` で通知する。
- 動きは実行中表示だけにし、`prefers-reduced-motion` で止める。
- API・ユーザー入力は `textContent` で表示し、HTMLとして解釈しない。
