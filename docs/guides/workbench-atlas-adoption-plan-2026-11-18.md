# Workbench 新UI（Shirokuma Atlas）適用ワークプラン

2026-11-18 JST。オーナーが [Shirokuma Atlas モックアップ](../design/assets/ui_mockups/shirokuma-atlas.html)（`03ece343`）を新UIとして確定した。
本書は、この見本を現行Workbench（`tools/local_experiment/workbench/`、配信は `workbench_server.py`）へ適用する作業単位と完了条件を定める。

## 方針

- 見本はサンプルデータで動く参照実装であり、本番へそのまま差し替えない。現行Workbenchを残したまま、画面単位で作り替える。
- 現行のUIテスト（約50ファイル・2.3万行）は本番 `index.html` のスクリプトを Node と簡易DOMで動かし、要素IDと状態遷移を前提にする。要素IDは原則として残し、変えるときは同じWPでテストも意図的に直す。
- バックエンドのAPIと業務ロジックは原則変えない。必要なものは各WPに「要API」と明記する。
- 日英の切替を維持する。新しい文言は日本語・英語の両方を `base_i18n.js` に登録する（見本は日本語のみ）。
- 権限再確認、取消、UNKNOWNの照合、公開履歴、古い応答の破棄など既存の契約は変えない。
- DEV-04F の Commander–Worker 方式で進め、各WPを codex-cli に渡して差分と検証結果をレビューする。

## 共通ルール（全WPで守る）

1. **画面構成**：左にナビ、上部バーにパンくず・環境バッジ・コンピュート状態・⌘K・「SQL を開く」。日付は出さない。ページ見出し直下に定型の説明文を置かない。
2. **状態の一致**：画面ごとに独自判定せず、サーバーから得た同じ状態を各画面に反映する（休止中はSQLを止める、利用終了したDBは選択肢から外す、照合済みの処理は休止を妨げない）。
3. **影響の表示**：全件置換・公開の置き換え・利用終了・休止では、確定ボタンの直前に影響を1行で出す。ボタン名に影響を書き（例：「3 行を削除して置き換える」）、赤いボタンにする。
4. **メッセージ**：その画面の操作で出たものだけを表示する。画面を移るときは引き継ぎのメッセージだけを持ち越す。同じ内容は1か所にだけ出す。
5. **次の操作**：成功後の主ボタンは1つ（READY後は「SQLで使う」、公開後は「公開テーブルを開く」）。
6. **表記**：時刻は `YYYY-MM-DD HH:MM JST`、日時入力もJST。UTCは監査記録の詳細だけ。用語は「利用終了」に統一し、状態名に英語を添えない。
7. **アクセシビリティ**：320/390pxで横スクロールなし、タップ領域44px、フォーカス枠は常時表示、`role="status"` / `alert`、矢印キー移動。[UIデザイン規則](workbench_ui_design.md)を引き継ぐ。

- [UIデザイン規則](workbench_ui_design.md)に共通ルール1〜7を Atlas 版として追記する。

### UX-A1 共通の画面枠と共通部品

- 左ナビを「データを扱う」「運用管理」「お気に入り」「ワークスペース」に分け、ラベルを改行させない。
- 上部バーにコンピュート状態を加え、日付を外す。言語・ロール・AI設定はユーザーメニューへ。
- ⌘Kパレット：ページ・操作・テーブル・DBを検索し、矢印キーで選ぶ。権限のないテーブルと利用終了したDBは出さない。
- 共通部品：画面単位のメッセージ、影響表示ブロックと赤い確定ボタン、`fmtJST`、用語辞書（日英）。
- テスト：`test_workbench_navigation_ui.py`・`test_workbench_explorer_compute_layout_ui.py` を更新し、パレット・メッセージの出し分け・時刻表示の試験を追加する。

### UX-A2 ホーム

- 新設し、最初に開く画面をSQLワークシートからホームへ変える。
- 「確認が必要」に、結果不明の実行、休止中・状態不明のコンピュート、利用終了の途中のDB、品質検査の失敗、失敗したジョブ・アラートを既存APIから集めて出す。

### UX-A3 データ探索とSQLワークシート

- 結果をエディター直下に置き、実行時の文脈（DB／スキーマ／ロール／実行範囲）と状態表示を1か所にまとめる。
- 実行ボタンは選択に応じて「▶ 選択範囲を実行」「▶ 全文を実行」。休止中・切替中は実行を止め、理由をボタンの横に出す。
- 利用終了したDBを選択肢から外す。データ探索からワークシートへ DB・スキーマ・ロールを引き継ぐ。
- 要API：DBをまたいだオブジェクト検索。現行カタログAPIがスキーマ単位なら、権限で絞った検索APIを追加する。

### UX-A4 取り込み・ステージとデータ変換

- 各段階で主ボタンを1つだけ出す（取り込み → 保存 → 候補の構築 → 品質検査 → 公開の確認 → 公開）。
- 影響の行：取り込みは方式（作成・追加・全件置換・キーで更新）ごとの行数と下流の変換、公開は既存行数と参照中のロール。
- 要API：取り込みプレビューの応答に既存行数・更新行数・追加行数を加える（既に返していればそれを使う）。下流の変換は既存の dbt グラフ・リネージから取る。
- AI Bears から渡された下書きは「次: RAWを選ぶ」の1行だけで受け取る。

### UX-A5 データベース管理

- 一覧の状態名を「利用終了」に統一する。
- 作成の確認画面に担当チームを加える。要API：作成要求に担当チームを含め、保存・表示する。
- READY後は「SQLで使う」を先頭にし、利用終了は「管理」の下へ移す。
- 利用終了の確認では、アクセスが終わる利用者（既存の権限API）を出し、確定前は影響を1行の要約にする。開始 → 観測 → 照合 → 完了は `database_retirement` の現行の仕組みを使う。

### UX-A6 ジョブ・監査ログ・AI Bears・コンピュート & ガバナンス

- ジョブ：見本の形に合わせ、作成・ステップ・スケジュール・アラートを残す。
- 監査ログ：時刻をJSTにし、範囲・発生元を日本語で表示、狭い画面では絞り込み条件を折りたたむ。
- AI Bears：ワークシート・データ変換への受け渡しをそろえ、「WAP」は「データ変換」と表記する。
- コンピュート & ガバナンス：休止確認に影響を受けるジョブ・ワークシートを出し、閲覧者も状態を更新できるようにする。自動休止とAI設定をここへ移す。
- 要確認：休止を妨げる処理の判定はサーバーが持つ。照合済みの処理は妨げにならないという見本の扱いがサーバー側の意味と一致するかを確かめ、ずれていればサーバー側に合わせる。

### UX-A7 旧UIの撤去と受入

- 使われなくなったCSS・要素ID・翻訳キーを削除する。
- `make verify-local-experiment` と `make verify-design-context` を通す。
- 受入：取り込み → 公開 → 監査記録、データ探索 → SQL、DB作成 → 利用終了、AI Bears・コンピュートの4シナリオを、1440/390/320px・日英・キーボード操作でオーナーが確認する。
- 記録はDEV-04Fの書式（3〜5行）で残す。

## 実施体制

実装・テスト実行は OpenCode（`opencode-go/deepseek-v4.1-flash`、variant `max`）に委任する。
Claude Code はWPごとに依頼内容を固定し、差分・テスト結果・ブラウザー確認を独立に評価して採否を決め、本書の状態欄を更新する。
評価が合格なら、オーナーの判断を待たずに次のWPを開始する（2026-11-19 オーナー指示）。コミットはオーナーの依頼があるときだけ行う。
