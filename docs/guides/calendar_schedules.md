# 日時・曜日・月次スケジュール

## 対象と構成

登録ジョブとステージの自動取込で、同じ5種類の予定を設定する。
ジョブに含まれるアラート判定にも適用する。
Phase 19.2の[登録マートの定期確認・自動更新](scheduled_marts.md)も同じ予定計算と停止・復旧の扱いを使う。
既存Workbenchのスケジューラ、SQLite台帳、実行器、履歴、排他制御を再利用する。
追加サービス・依存ライブラリ・外部cronは導入しない。

| 種類 | 入力 | 例 |
|---|---|---|
| 一定間隔 | 1〜10,080分 | 30分ごと |
| 1回のみ | 日付・時刻・タイムゾーン | 2026-11-01 09:00に1回 |
| 毎日 | 時刻・タイムゾーン | 毎日02:00 |
| 毎週 | 1つ以上の曜日・時刻・タイムゾーン | 月・水・金の09:00 |
| 毎月 | 1〜31日または月末・時刻・タイムゾーン | 毎月1日、または毎月末日の02:00 |

時刻は分単位、タイムゾーンは既定で `Asia/Tokyo`。
毎月31日を選んだ場合、31日のない月は実行しない。月末を選べば2月・閏年も含めて最終日に実行する。
曜日は複数選択できる。毎月の第何曜日、休日カレンダー、cron式は対象に含めない。

## 実行・停止・再起動

- 1回のみの予定は、有効化時に未来の日時を要求する。無効な下書きには過去の日時を保存できる。
- 予定受付と台帳の更新を同じトランザクションで行い、1回のみの予定はその時点で自動的に無効化する。
  成功・失敗・結果不明・競合や遅延によるスキップ後に自動再実行しない。再実行には新しい未来日時の保存が必要。
- Workbench停止中・ホストのスリープ中は実行しない。予定から60秒以上遅れた場合はスキップを記録する。
  再起動前の未来の予定は保持し、過去の予定をまとめて追いつき実行しない。
- 毎日・毎週・毎月は、スキップしても次の該当日時へ進む。権限失効や入力不備の場合は予定を停止する。
- 夏時間で存在しない時刻は、1回のみでは保存時に拒否し、繰り返しではその日を省略する。
  同じ時刻が2回来る日は最初の1回を使用する。内部の実行予定はUTCで保存する。
- 同時実行は既存の全体1件制限を維持する。競合時の待ち行列は作らない。
- 予定を無効にすると新しい受付を止める。受付済み（待機中・実行中）の処理は中断しない。
- ステージの対象は `append` / `upsert`。保存設定の版照合、所有者・権限、内容単位の重複防止を維持する。
  1回のスキャンは最大10ファイルのため、1回のみの予定で大量の残りファイルを自動処理し続けることはない。
- バックアップ復元時は全種類の予定を無効化する。元の日時・曜日・月次設定は保持する。

## APIと互換性

既存の `POST /api/jobs/schedule` と `POST /api/stages/schedule` を使う。
ジョブは `name` / `arguments` / `enabled`、ステージは `name` / `enabled` と有効化時の `version` に、以下の設定を加える。

| `kind` | 設定フィールド |
|---|---|
| `interval` | `every_minutes`（整数） |
| `once` | `date`（`YYYY-MM-DD`）、`time`（`HH:MM`）、`timezone` |
| `daily` | `time`、`timezone` |
| `weekly` | `weekdays`（月曜1〜日曜7の重複しない整数配列）、`time`、`timezone` |
| `monthly` | `day_of_month`（整数1〜31または文字列 `last`）、`time`、`timezone` |

```json
{
  "name": "refresh_marts",
  "kind": "weekly",
  "weekdays": [1, 3, 5],
  "time": "02:00",
  "timezone": "Asia/Tokyo",
  "arguments": {},
  "enabled": false
}
```

不要な種類のフィールドは送らない。既存ステージAPIの `kind` 省略は一定間隔として受け付ける。
`{"name":"refresh_marts","enabled":false}` の最小停止操作は維持する。
既存SQLiteの予定・実行履歴を保持して列を追加する。バックアップ形式は変更しない。
