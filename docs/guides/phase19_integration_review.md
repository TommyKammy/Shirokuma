# Phase 19.1–19.2 最終レビュー・統合検証

検証日: 2026-10-18

## 判定と変更

[手動更新](managed_marts.md) と [定期確認・自動更新](scheduled_marts.md) をまとめて確認し、
対象範囲に未解決の機能上の指摘はない。新しいサービス・依存・台帳は追加していない。

復旧判定の履歴読込を軽量化した。`_requires_manual` が取得する候補を
「結果不明」または「手動成功」に絞り、通常の変更なし確認・スキップ・失敗を読み飛ばす。
判定順序と成功内容の検査は維持する。多数の変更なし確認があっても未解決の結果不明を隠さず、
手動更新成功だけで復旧する回帰テストを追加した。

## 確認結果

| 観点 | 確認した動作 |
| --- | --- |
| 手動・自動の連携 | 手動成功で監視基準を保存。直後の定期確認は変更なし。元データ更新後だけ自動公開し、手動では変更がなくても更新する。 |
| 変更検知 | 明示した監視元のスナップショットを比較。更新前の値を基準に保存し、実行中の変更を次回検知できる。ロールバックも変更として扱う。 |
| 変更なし・品質不合格 | 変更なしではWAPを実行せず最終更新成功時刻を維持。品質不合格では既存公開テーブルを維持し、自動更新を停止する。 |
| 権限・版 | 保存・実行・予定開始で所有者と管理者権限を確認。実行前の権限低下や認証モード変更、古い版を拒否する。 |
| 重複・停止 | 既存の全体ジョブ排他を利用。実行中の再要求・定義変更は拒否。停止は受理済み処理を中断せず、次の自動開始を止める。 |
| 再起動・復元 | 正常な定義・基準・予定を保持。過去枠をまとめて再実行しない。残った実行中履歴は結果不明とし、対象の予定を停止する。 |
| 結果不明の復旧 | 公開済みでも台帳の完了が不明なら自動再実行しない。失敗・スキップでは復旧扱いにせず、手動更新成功を確認してから自動更新を有効化できる。 |

## 維持する制約

更新は既存WAPによる全件置換。スナップショットが変わらないスキーマ変更、未指定の入力、
外部データ、現在時刻に依存するSQL、公開先への直接変更は自動検知しない。必要時は手動更新する。
入力全体を同じ瞬間に固定するトランザクションや、公開・基準保存・台帳更新をまたぐ原子性は保証しない。
結果不明時は公開先を確認し、所有者が手動更新に成功した後で予定を再開する。

実際の月替わりや長時間運用は今回の実機検証に含めない。曜日・月末・タイムゾーンの境界は既存の制御時刻テストで扱う。
本記録はローカル実装の技術検証であり、運用者による業務データでの受入を代替するものではない。
