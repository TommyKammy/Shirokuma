# Phase 17.1〜17.3 最終レビュー・統合検証

2026-10-18。登録ジョブ、スケジュール、アラートを一連の機能として再評価した。
対象は専用ローカルラボでの利用。既存の単体・HTTP・実機検証に加え、
別プロセスのWorkbenchを再起動しながら操作する統合試験を追加した。

**判定：専用ローカルラボでのPhase 17.1〜17.3の技術検証を完了。**
検出した2件は修正済みで、修正後の独立レビューに未解決の指摘はない。

## 検出した問題と修正

| 重要度 | 問題 | 修正と再現確認 |
|---|---|---|
| P2 | 取込ファイルの解析で `csv.Error` または `decimal.InvalidOperation` が発生すると、スケジューラの確認処理全体が中断し、後続の正常な予定も実行されない | ジョブの入力前検証で、この2種類の解析例外を安全な入力エラーへ変換。不良予定だけを停止し、同時刻の正常ジョブが実行される回帰試験を追加。手動HTTP実行も受付前に400となり、ファイル内容を応答へ出さない |
| P2 | 共有認証ガイドどおりHTTPSプロキシ経由で利用すると、正規の同一HostのOriginも403となり、ジョブ保存・実行などができない | POSTとCORSの判定を共通化し、共有モードでは同一HostのHTTPS Originを許可。別Host、転送ヘッダーによる偽装、ローカルモードのHTTPS Originは拒否する契約試験を追加 |

修正は既存の入力前検証とHTTP入口に限定した。実行器、常駐プロセス、外部依存は追加していない。
HTTPSプロキシ側では元のHostを保持する。[共有認証ガイド](shared_http_authentication.md)を参照する。

## 統合検証の範囲

| 確認項目 | 方法と確認内容 |
|---|---|
| ジョブ→スケジュール→アラート | 実際のHTTP APIからデータ作成者として型付き引数のSQL書込みとアラートを登録。実時刻の1分後に、標準のWorkbenchスケジューラが実行し、関連実行ID付きの通知を作成 |
| 予定保存後の再起動 | 次回実行前にHTTPプロセスを終了・再起動。所有者、選択ロール、認証モード、次回時刻が保持され、その予定が1回だけ実行される |
| 定期実行と手動実行の連携 | 同じ定義・引数で手動実行し、定期実行で生じた通知のIDを維持して回数を更新。確認済み状態を保ち、実テーブルの条件解消・再発で解消と新規通知を確認 |
| 権限失効 | 別所有者の予定保存後、その共有アカウントを閲覧者へ変更して再起動。予定時刻に実行を拒否し、予定を無効化。権限を保った所有者の予定は実行される |
| HTTPの境界 | 未認証・閲覧者の取得拒否、上位ロール指定の拒否、他人のジョブ実行拒否、管理者を含む他人の通知確認拒否を実際の認証付きHTTPで確認 |
| 確認後の再起動 | 通知を確認してから再起動。通知ID・確認者・確認時刻・履歴を保持し、消費済み予定の再実行がないことを確認 |
| プロセス強制終了 | 通知成功・確認後、次の処理が待機中の子プロセスをSIGKILL。新しいプロセスで、成功済み処理を維持、実行中を結果不明、未開始をスキップとして復旧。通知と確認状態を保持し、自動再実行しない |
| バックアップ復元 | 有効な予定を含む台帳を既存のバックアップ処理で保存し、空の別ディレクトリへ復元。復元先でHTTPサーバーを起動し、通知・確認・履歴の保持と全予定の無効化を確認 |
| 遅延・競合・認証モード変更 | 既存スケジューラ回帰で、60秒以上の遅延、実行中との競合、複数プロセス、ローカル／共有モード切替、日次の夏時間を確認 |

HTTP統合試験は一時台帳・合成アカウント・固有名の合成Icebergテーブルを使い、
実際のTrino資格情報とCAで実行する。通常利用の台帳や共有アカウントは変更しない。
プロセス強制終了試験は実OSプロセスとSQLiteを使うが、SQL／条件の実行部分はテスト用に置換する。
HTTPS Originの修正は実HTTPハンドラーへのヘッダー契約で検証し、外部向けプロキシの配備は行わない。

## 運用上の境界

Workbenchサーバー稼働中に予定を処理する。停止・スリープで60秒以上遅れた予定の追いかけ実行はなく、
同時に1ジョブだけ実行する。再起動で有効な予定は継続するが、バックアップからの復元では予定を停止する。

SQLの反映とローカル台帳を一つのトランザクションにできないため、
強制終了した実SQLの取消・反映結果や、障害をまたぐexactly-onceは保証しない。
結果不明の実行は反映先を確認してから手動で再実行する。

今回の判定は合成データを使う専用ローカルラボの技術検証であり、業務データ・本番運用の受入を代替しない。

機能別の使い方は[登録ジョブ](registered_jobs.md)、[スケジュール](scheduled_jobs.md)、[アラート](alerts.md)を参照する。
