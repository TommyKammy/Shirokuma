# データベース探索のテーブル選択高速化

## 実装範囲

テーブル選択では開いているインスペクターの情報だけを取得する。初期表示はカラム定義とし、プレビュー・統計・DDL・スナップショット・リネージは各タブを開いたときに取得する。カラム画面内のスナップショット重複表示を専用タブに集約した。

`GET /api/catalog?table=…&detail=…` に次の取得範囲を追加した。従来の省略時・`full`・`snapshot_id` の形式は保持する。

| detail | metadata 内のキー | 通常のSQL数 |
|---|---|---:|
| columns | columns | 1 |
| preview | preview | 1 |
| profile | profile | 4 |
| ddl | definition | 1 |
| snapshots | snapshots | 1 |
| lineage | lineage_detail | 0 |

`full` は取得済みカラムを監査処理に渡し、通常8本だったSQLを7本に減らした。監査・ロールバックで必要な「現在有効なスナップショット」の判定は保持する。履歴の新しい順で代用しない。統計には全行集計が含まれ、大きなテーブルでは時間がかかるため、初回選択から切り離す。

## キャッシュと整合性

- ブラウザのページ内メモリだけを使い、最大64件・取得から15秒で期限切れになる。再利用で期限を延長しない。追加ライブラリ・サービス・永続キャッシュは使わない。
- 認証主体・ロール・テーブル・取得範囲で分離する。同じ情報を取得中の要求は共有し、エラーは保存しない。
- キャッシュ利用時は軽量なセッションAPIで現在の権限を再確認する。ロール変更や認証失敗では、キャッシュと表示中の詳細を消去する。
- SQL実行・取込・複製・削除・Data Bearによる書込・dbt buildなどの開始と終了で無効化する。途中失敗や結果不明でも古い情報を残さない。
- ジョブ・ステージ・更新対象の既存の状態取得で変化を観測した場合も無効化する。取得中の応答が遅れて届いても、古い選択・権限・更新前の情報で表示を上書きしない。
- 他のブラウザ・CLI・未観測のスケジュールによる更新は、次の選択時の期限判定、または明示的な更新で反映する。表示中のデータを常時監視する仕組みは追加しない。

## 検証記録

実画面比較は同じローカルWorkbench、同じブラウザ、同じ2テーブル（`marts.fct_orders` と `tpch_tiny.nation`）を使う。選択順は fct_orders → nation → fct_orders → nation → fct_orders → fct_orders。

「表示確認時間」は自動操作のクリック開始からカラム表の可視確認までであり、ブラウザ操作ツールの往復時間を含む。「API応答時間」はブラウザのネットワーク計測値であり、描画時間を含まない。

改修前の表示確認時間: 784 / 685 / 677 / 669 / 696 / 675 ms。
改修前のAPI応答時間: 649 / 549 / 559 / 571 / 561 / 547 ms。全6回で詳細APIを呼び出し、通常8 SQLを実行した。

改修後の表示確認時間: 276 / 272 / 282 / 279 / 276 / 281 ms。

| 同じ操作での比較 | 改修前 | 改修後 |
|---|---:|---:|
| 最初の2テーブルのAPI応答 | 649 / 549 ms | 69 / 78 ms |
| 再選択4回のAPI応答 | 559 / 571 / 561 / 547 ms | セッション確認が各1 ms |
| 6操作の表示確認時間の中央値 | 681 ms | 277.5 ms（約59%短縮） |
| テーブル詳細APIの呼出回数 | 6 | 2 |
| 通常のテーブル取得SQL数 | 48 | 2 |

再選択ではテーブル詳細APIを呼び出さず、セッション確認後にメモリ上の情報を表示した。1 msはAPI応答時間であり、画面全体の描画時間ではない。表示確認時間には自動操作の往復・待機が含まれるため、純粋なクリックから描画までの時間や、全環境での応答保証には使わない。測定時は稼働中のローカルWarehouseを使用し、休止からの起動時間は含まない。

### 実画面・実機検証

- 各詳細タブを開いた時だけ対応するAPIが1回呼ばれ、データ・統計・DDL・履歴・リネージを表示できた。
- 管理者から閲覧者へ切り替えると、旧テーブル詳細が消去され、一覧がmartsだけになった。raw/sandbox/staging/tpch_tinyの詳細APIは全取得範囲で403。閲覧者のDDL取得にはTrinoの既存制限による拒否が表示され、権限を緩めていない。
- 一時テーブルを作成し、ワークシートのCREATE OR REPLACEによるカラム変更、外部API更新後の「詳細を更新」、16秒待機後の再選択による期限切れ再取得を確認した。ALTER TABLEは既存SQLポリシーで拒否され、検証は許可済みの操作で行った。
- 18桁のsnapshot IDを変えずにTime Travelプレビューできた。過去・現在とも1行、差分0を確認した。
- 一時テーブル削除後、一覧から消え、選択も解除された。検証用テーブルは残していない。
- Workbenchを既存のTrino認証・TLS設定で再起動し、最終`/api/status`は`healthy`。ジョブ履歴7件を保持し、実行中ジョブは0件。
- `shirokuma doctor`はcluster/policyがhealthy、Fluxの`flux-system` Kustomizationがsuspendedのため全体はdegraded。今回の改修ではFlux設定を変更していない。

独立レビューで指摘された、遅延したジョブ履歴による空表示と、外部権限降格時のセッション確認を修正した。無効化後は「詳細を更新」の案内を出し、古い詳細に対する操作を停止する。認証・権限エラー時も理由と復旧方法を表示する。
