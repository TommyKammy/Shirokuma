# WebUI高速化の最終レビュー・統合検証

検証日: 2026-10-19。レビュー基準: `0846beb2`。対象は `374a9dd5`、`7ea47d11`、`0846beb2` の探索・状態・ジョブ・ステージ・マート・監査取得の変更と、その連携。

## レビューで見つかった問題

| 修正した問題 | 発生条件 | 修正内容 |
| --- | --- | --- |
| Jobsの一覧更新とポーリング再開が中断する | 一覧またはスケジュール取得中に別ジョブを開く／新規作成する | 選択フォームの応答保護と、一覧・実行履歴の更新条件を分ける |
| 探索画面の読込中表示が終わらない | 探索取得中に、前画面の遅延したジョブ／マート応答がキャッシュを無効化する | 古い応答は捨て、同じ要求・権限で世代だけが変わった場合は再取得の案内を表示する |
| 権限切替後にJobsの旧表示が残る | 新しいロールの取得が失敗・遅延する、または旧通知・保存応答が後から返る | ロール／セッション切替時にJobsの状態と表示を消し、既存のrole・stageEpochで通知／保存の成功・失敗両方を保護する |

最初の2件は今回の高速化で加わった競合、3件目は権限切替の横断確認で見つかった既存問題。3件目はAPIの認可突破ではなく、ブラウザーに既に取得した内容の表示が残る問題である。

## 実環境での統合試験

通常のWorkbenchとは別の一時状態ディレクトリとHTTPリスナーを使い、既存のTLS／パスワード認証されたTrino・Icebergで次の3件を実行した。244.848秒で全件成功した。

- `test_http_restart_scheduled_to_manual_alert_lifecycle_and_revoked_owner`: 予約から手動実行への連携、アラート、HTTPサーバーの再起動、所有者権限の変更。
- `test_manual_schedule_export_roundtrip_restart_and_changed_content`: 手動・自動取込、重複防止、ステージ出力と再取込、再起動、ファイル内容変更。
- `test_scheduled_mart_real_snapshots_quality_repair_restart_and_restore`: Icebergの実スナップショットによる変更検知、品質検査、修復、再起動・状態復元。

一意な名前の使い捨てテーブルと一時ファイルを使い、既存の後処理で削除した。外部サービスへの通知・公開は行っていない。

## 実画面・再起動確認

変更前の実画面でも、Jobsの詳細表示後に通信を一時停止してadminからdata_engineerへ切り替えると、旧詳細と7件の履歴が残ることを確認した。通信制御は直後に解除した。

探索では初回に `detail=columns` だけが取得され、15秒以内の再選択は `/api/session` の権限確認だけで表示された。期限を過ぎた再選択ではカラムを再取得した。

通常Workbenchの再起動前の状態は、登録ジョブ2件・実行履歴7件・ジョブ予約1件・登録ステージ0件・登録マート0件。Warehouseはactive、自動Chillは0分（無効）。

修正後の実画面で、次を確認した。

- 通信失敗中のadmin → data_engineer切替直後に、旧履歴7件が0件になり、実行詳細は空になる。通信復元後にadminへ戻すと7件を再取得して表示する。
- `/api/jobs` の応答を一時保留し、新規ジョブ入力を開始してから応答を再開しても入力値は保持され、スケジュール・実行履歴・通知の取得が続く。定義は保存していない。
- Jobsの実行履歴応答とカタログ一覧応答を一時保留し、探索へ移動後にJobs応答を先に再開すると、探索／Worksheet双方のツリーが日本語の再取得案内に戻る。「カタログを更新」で復旧し、その後の再選択キャッシュも機能する。
- data_engineer / bi_viewerではステージ・マート管理操作が非表示になり、bi_viewerではJobsタブも非表示になる。監査ログは両ロールで100件を表示する。
- ステージとマートの未登録時は登録案内を表示する。通常Workbenchに既存登録がないため、非空の取込・更新・出力連携は分離HTTP統合試験で確認した。

通信保留・オフライン設定は試験後に解除した。未保存の試験入力はタブ再読込で破棄し、既存のジョブ定義やWorksheetは変更していない。

通常Workbenchを停止・再起動し、再起動前後の上記5種類のAPI応答内容を照合してすべて一致した。停止中の取得失敗が表示され、再起動後は更新操作で復旧した。Warehouse active・自動Chill 0分も維持し、Workbenchは起動状態にある。

通信削減が保たれることも修正後に確認した。

| 操作 | 取得 |
| --- | --- |
| Computeを表示 | `/api/status` 1回 |
| Jobsを表示 | jobs / schedules / runs / alerts 各1回 |
| 詳細選択済みの実行履歴を更新 | runs / alerts / schedules 各1回。detail再取得なしで1ステップの詳細を保持 |
| 監査画面を表示 | pawprints / history?mode=runtime 各1回 |
| 15秒以内に探索の同じテーブルを再選択 | session確認のみ。カラム詳細の再取得なし |

## 最終検証結果

- 重点テスト: 322件成功。探索・状態・Jobs・MartsのUI、Workbench API、Bears、Warehouse、ジョブ／マートのスケジューラを対象とした。
- `make verify-local-experiment`: 619件中588件成功・31件スキップ。任意のpyarrow依存と明示有効化が必要な実環境試験がスキップ対象。前述の実環境3件は別途有効化して全件成功した。
- `make verify-design-context`: 14件成功、設計コンテキスト検査成功。
- 既存テストは削除せず、7件追加。従来「選択が変わったら一覧を捨てる」としていた期待値を、下書き保護と最新一覧の保持へ修正した。
- 全体検証で見つかったカレンダーテストの抽出JavaScriptハーネスの初期化不足を補正した。時刻計算・保存／停止・権限の期待値は変更せず、再実行で成功した。

- 通信障害を解除してページを再読込後、対象全画面を巡回し、ブラウザーの新しい警告・エラーは0件。
- `bin/shirokuma doctor`: cluster / policyはhealthy。Fluxの既存suspended設定による総合degradedは継続し、今回変更していない。
