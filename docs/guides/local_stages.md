# ローカルステージ（Phase 18.1）

## 目的と構成

Workbenchを動かしているホストのフォルダに名前を付け、直下のファイルを選んで手動取込する。
既存のファイル読取・プレビュー・取込処理と、[登録ジョブ](registered_jobs.md)の
排他制御、バックグラウンド実行、処理履歴を利用する。
設定と履歴は `SHIROKUMA_STATE_DIR/jobs.sqlite3` に保存する。
追加サービス、依存ライブラリ、監視スレッドは不要。

## 操作

1. 管理者として「データ取込」のローカルステージを開く。
2. ステージ名、ホスト上の絶対フォルダパス、取込先テーブル、取込方式、形式を登録する。
3. ステージを選び、一覧から1ファイルを選択してプレビューする。
4. ファイル名、取込先、方式、行数とサンプルを確認し、手動取込する。
5. ジョブの実行履歴で成否・取込件数を確認する。

ブラウザを開いているPCのフォルダ指定ではない。登録先はWorkbenchの実行ホストに存在する必要がある。
ブラウザからの一時アップロードは従来の取込フォームを利用する。

ステージには取込先と方式を固定する。`append` は追加、`replace` は選択ファイルで全件置換、
`upsert` は指定したキーによる更新・追加。`upsert` には入力列に存在するキーが必要。
ファイル一覧からの要求で取込先・方式・フォルダを上書きすることはできない。

## ファイルと権限

- 管理者だけがステージAPIを利用できる。他の管理者の設定は一覧で確認できるが、
  更新・ファイル一覧・プレビュー・取込は所有者だけが行える。
- 共有モードでは実行直前にもアカウントと管理者権限を再確認する。
- フォルダ直下のCSV、TSV、JSONL、NDJSON、JSON、Parquetを扱う。
  隠しファイル、未確定の拡張子、サブフォルダは取込対象にしない。
- 単一ファイルは25 MiBまで、ディレクトリ確認は1,000エントリまで。
  プレビューは最大10行を表示するが、既存の読取処理はファイル全体をメモリに保持する。
- 登録フォルダ外への参照、絶対ファイル名、親ディレクトリ参照を拒否する。
  標準ライブラリのパス解決を用い、外部のファイルアクセスサービスは追加しない。

一覧・プレビュー・受付では保存設定の版とファイルのサイズ・更新時刻を照合し、
実行時にも受付済みのファイル情報を照合する。変更された場合は一覧とプレビューをやり直す。
確認画面の取込先と方式にはプレビュー応答の設定を使い、別画面での設定変更による表示の食い違いを防ぐ。
これは内容の暗号学的な識別やファイルの排他ロックではない。
生成側は一時名で書き込み、完成してから確定名へ移動し、取込完了まで変更しないこと。

## 実行履歴と再起動

1回の取込は `trigger=stage`、`job_name=stage:<ステージ名>` の実行として記録する。
受付時のステージ設定と選択ファイルの情報を保存するため、後から設定を変更しても
実行中・過去の取込先や方式は変わらない。代理の登録ジョブやスケジュールは作成しない。

通常ジョブと同じ排他ロックを使用する。他のジョブが実行中なら競合として拒否し、待ち行列は作らない。
取込では既存の `atomic_append=True` を使用する。途中のworker喪失は `unknown` とし、自動再実行しない。
Icebergの更新とSQLiteの完了記録は別の処理なので、結果不明の場合は取込先を確認してから再実行を判断する。

**Phase 18.1では処理済みファイルの自動除外を行わない。** 手動で再度取込すると、
`append` は同じ行を追加する。ファイル単位の処理済み台帳と定期確認はPhase 18.2の対象。

通常の再起動では設定と履歴を保持する。既存のバックアップ・復元にはSQLiteの設定と履歴が含まれるが、
登録元フォルダのファイルは含まれない。復元先ではフォルダと原本を別途用意する。
フォルダや原本が存在しない場合は明示的に失敗し、作成や代替ファイルの探索は行わない。

## HTTP API

すべて管理者限定。利用者とロールは既存HTTP認証で決定する。

| Method / path | 入力 | 結果 |
|---|---|---|
| `GET /api/stages` | なし | `stages` 一覧 |
| `POST /api/stages/save` | `name`, `directory`, `table`, `mode`, `format`, 任意の `key` | 保存した `stage` |
| `POST /api/stages/files` | `name` | `files`、上限情報 |
| `POST /api/stages/preview` | `name`, `file`, `version` | 列、行数、サンプル、ファイル版、確認対象の `stage` 設定 |
| `POST /api/stages/import` | `name`, `file`, `version` | HTTP 202、`run` |

`version` はサーバーの一覧・プレビューが返した値をそのまま渡す。
履歴と詳細は既存の `/api/jobs/runs` と `/api/jobs/detail` を利用する。
